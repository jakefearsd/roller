## What Package A shipped, task by task

### A1 — Frontend build wiring (commit `fb9c3d15e`)
`frontend-maven-plugin` added to the parent `pluginManagement`; three
executions in `app/pom.xml` (`install-node`, `npm-ci`, `npm-build`) at
`generate-resources`. Node pinned to the newest 22.x LTS resolved at

### A2 — The CodeMirror 6 editor core (commit `e60922d44`)
`app/frontend/src/editor.js` (CM6 wiring: state, view, markdown language,
search, autocomplete, bracket matching, custom keymap), `markdown-theme.js`
(design-token-only syntax highlighting, no hex literals), `stats.js`
(word count / reading time), `shortcodes.js` (shortcode-aware autocomplete
source). Node's own test runner (`node --test`) covers `stats.js`/
`shortcodes.js` directly (3 tests), wired into Maven's `test` phase behind
`${skipTests}`. **Open, unresolved decision carried forward from this
task:** the bundle measured 561.4 KB minified / 196 KB gzip, about 12% over
the brief's 350–500 KB estimate, traced to `@codemirror/lang-markdown`'s
`markdown()` unconditionally pulling in HTML/JS/CSS embedded-language
support via a non-optional default parameter. Fixing it means dropping
`markdown()` for a bare `markdownLanguage`, which loses fenced-code-block
language switching and HTML-tag autocomplete — a real feature trade, not a
config flip. No later task in this package revisited it; still open.

### A3 — Switch the entry editor to RollerEditor, migrate the browser tests (commits `8eb79a037` + fix round `01d984ae1`) — IT gate
`EntryEditor.jsp`/`PageEdit.jsp` mount CM6 instead of EasyMDE; `head.jsp`'s
EasyMDE/Font Awesome `<c:if>` replaced by the bundle+CSS `<c:if>`; all 25 IT
classes' `.CodeMirror` selectors migrated to a new `Editor` test helper.
**Found and fixed a real defect in A1's output**: the bundle's build
location (`target/classes/static/...`) is unreachable in this deployment
(the `DispatcherServlet` is `*.rol`-only, so Spring's classpath static
handling never runs; the Boot executable WAR's `WEB-INF/classes` nesting
also can't be opened by static-resource scanning). Moved the outfile to
`app/src/main/webapp/roller-ui/scripts/roller-editor.js` — a build output
living under `src/`, deliberately, because it is the one path that works
both under `spring-boot:run` and inside the packaged WAR; git-ignored,
pinned by `EditorBundlePomTest`. **Fix round 1 (post-review) found a real
functional bug**: `Ctrl+Enter` inside the editor was eaten by CM6's own
`defaultKeymap` (`insertBlankLine`) before the document-level publish
handler ever saw it — fixed with a `Prec.highest` host keymap for
`Mod-s`/`Mod-Enter`/`Mod-/` ahead of the combined keymap, verified by a
browser IT that failed for exactly that reason before the fix.
Full browser suite: 126/0/1-skipped, green first try, both before and after
fix round 1's edits.

### A4 — Theme-true preview shell, server side (commit `a35f1ab55`)
`PreviewServlet?shell=true` renders a bare shell (theme stylesheet + asset
macros + one empty `<article id="previewArticle">`) instead of the theme's
real page — a theme's own `_preview` template if it registers one,
otherwise a shared fallback, the same two-rung lookup `_page` already uses.
Read the real per-theme prose-wrapper class chains from each theme's own
`permalink.vm`/`_day.vm` rather than trusting the brief's illustrative class

from every shell (a live contact/subscribe form has no business posting
from unsaved preview text).

## Deferred items and open follow-ups, across the whole package

1. **A2 — bundle size, 561 KB vs. the ~350–500 KB estimate, unresolved.**
   Root cause traced (an unconditional HTML/JS/CSS embedded-language chain
   inside `@codemirror/lang-markdown`'s `markdown()`); fixing it costs
   fenced-code-block language switching and HTML-tag autocomplete. No task
   after A2 revisited this trade. Recommend a explicit decision (accept, or
   scope a follow-up task) before this ships further.
2. **A3 — the built bundle lives under `app/src/main/webapp/`,** not
   `target/`. Deliberate (it's the only path that works in both
   `spring-boot:run` and the packaged WAR — see A3's report), git-ignored
   and pinned by `EditorBundlePomTest`, but `mvn clean` does not remove it.
   A future task could register an extra Tomcat static-resource path or a
   `maven-war-plugin` `<webResources>` copy to get it out of `src/`, at the
   cost of `./roller dev` needing a second mechanism. Not blocking; recorded
   as a known wart.
3. **A9's `Pages.jsp` list-view URL bug is still live.** Every published
   page's row in the Pages list links to
   `${urls.weblogAbsolute(actionWeblog)}page/${p.slug}`, which 404s — the
   same bug A9 fixed on the editor's own permalink line, but not here,
   because `EditorJspMarkupHygieneTest.theCopyAndViewAffordancesArePresent`
   pins that exact wrong string as its assertion needle. Fixing this needs
   the JSP change and the test's needle updated in the same commit. Worth a
   short, dedicated follow-up task — it is a genuine 404 an author can hit
   today by clicking a link the admin UI itself renders.
4. **A9's shared writing guide mislabels Ctrl+Enter as "Post" on the page
   editor**, where that key saves rather than publishes (pages don't have a
   separate publish step the guide's copy distinguishes). Cosmetic;
   recorded rather than fixed, since correcting it costs a request
   attribute and a message key for a line nobody is likely to misread
   dangerously.
5. **A9's page-editor media chooser and writing guide have no browser
   coverage of their own** — `EditorSeoIT`/`ShortcodeCardIT` exercise them
   only on the entry editor. The markup is now genuinely shared
   (`EditorSurface.jsp`/`EditorScript.jsp`), so this is an argument, not a
   test; a future task could add a page-editor-specific assertion for
   either or both.
6. **A10 — `design-system.md`'s "## The cards (19)" heading's own arithmetic
   was already wrong before this task** (12 foundational + 5 named
   "Shipped reference cards" = 17, not 19, against an actual on-disk count
   of 18 before A10's new card). A10's new card happens to bring the true
   count to 19, coincidentally matching the stale heading — the heading's
   underlying math was never fixed. Cosmetic; a documentation-accuracy
   follow-up, not a test failure (`DesignCardsTest` does not read that
   heading).
7. **A10 — `newsletter.noList`'s sentence and its new dedicated link text
   both name "Weblog Settings"**, which reads slightly redundant now that
   the link has its own copy instead of reusing a generic key. The brief
   only asked for the link to carry its own key, not for the sentence's
   wording to change; a future copy pass could tighten this.
8. **Deferred, not forgotten, safety pattern for future work near
   `weblog.vm` and theme `*.css`:** three distinct hazards were found and
   fixed across A5 and A10, all in the same family — text that merely
   *looks* like a comment or *looks* like inert prose inside a
   Velocity-rendered file is not safe by default. (a) a bare zero-argument
   macro name (`#showX`) in any comment is invoked by Velocity, guarded now
   by `ThemeStylesheetTest` for theme CSS and by hand for `.vm` JS comments;
   (b) a literal bracketed shortcode name (e.g. `[map]`) anywhere in a
   Velocity-rendered file's output can trip a shortcode-leak regression
   test's substring assertion, independent of Velocity semantics — no
   automated guard exists for this second one yet, since it is a test/prose
   coincidence rather than a mechanism; write comments in plain English
   ("a map", "the showX macro") near any of these files.
