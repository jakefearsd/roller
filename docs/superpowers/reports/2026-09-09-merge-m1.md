## 1. Did the union build? No — and the reason is worth keeping

Both lanes were green in isolation and the union was not. `mvn -pl app
verify` at the merge commit: **4316 tests, 2 failures**, both naming
`EditorSurface.jsp`:

```
JspConsistencyTest.oneConfirmIdiomAndOneModalShape
  .modal-title on a heading element [EditorSurface.jsp: <h4 class="modal-title">]
AdminJspBugSweepTest.noHeadingLevelIsSkippedToH4OrH5
  [src/main/webapp/WEB-INF/jsps/editor/EditorSurface.jsp]
```

`EditorSurface.jsp` is Package A's file, extracted by task A9 *after*
Package B forked — so it is in neither scan's `A_OWNED` exemption, and both
of B's rules saw it for the first time at merge. One line fixed both
(`fix(merge): …`, `c5e8b58fc`).

**A second union-only break surfaced later, and it matters more**, because
the unit gate structurally cannot see it: `mvn -pl app verify` does not
compile `it-selenium` at all. `mvn verify -Pit` failed fourteen seconds in
with a compilation error — Package B added a test to
`WeblogConfigMatrixIT` that calls `executeJavaScript`, and Package A, in
the same file, replaced that class's only *other* `executeJavaScript` call
with the new `Editor` helper and removed the now-unused static import.
Both edits are correct in isolation; git merged both; the result does not
compile (`fix(merge): …`, `e56342acc`). Every other IT was swept for the
same shape and none had it.

The lesson for the next parallel wave: a clean `verify` on the app module
is not evidence that a merge is sound, and reading the merged files (§3)
did not catch this either — the import block scrolls past as noise. Compile
`-Pit` as part of the merge check, not as part of the gates at the end.

No merge dropped a hunk; see §3.

`weblogEntryQuery.date.toStringFormat` is deleted from the three bundles
that declared it, and `JspConsistencyTest` now fails if a bundle declares
it again. The key's real hazard was never the one call site: it is a
display *format* living in eight translated files that could disagree
(`ja` had `yy/MM/dd HH:mm` against the base bundle's `MM/dd/yy hh:mm a`).

**`A_OWNED` is gone.** Six scans across two classes skipped
`EntryEdit.jsp`/`EntryEditor.jsp`/`PageEdit.jsp` while the CodeMirror
rebuild owned them in a parallel worktree. All six now walk the whole tree,
and no replacement exemption mechanism was left behind.

**`Pages.jsp`'s page URL.** A published page is served at
`/<handle>/<slug>`; the list linked `/<handle>/page/<slug>`, the
CUSTOM-*template* route, which 404s. Both packages half-saw this: A fixed
the same shape on the editor's own address line and recorded the list as
still wrong; B then fixed a genuine but *different* defect on that exact
line (an unescaped slug in the href) and in doing so re-pinned the wrong
shape as a test's expected value. Three needles carried it. All corrected,
and `PageEditJspTest` now compares the two screens against **each other**
rather than against two independent literals — because what went wrong is
precisely that one was corrected and the other was not. `PageIT` fetches
the href off the row and asserts a 200.

**The B11 review's two follow-ups**, plus its CSS-comment minor:

- A **tree-wide href ratchet**: every `href="${…}"` value is
  `fn:escapeXml`'d, a `<c:url>` (declared into a var, or written inline),
  or a bare `urls.*` helper call. Stated tree-wide because the obvious
  grep is what missed the original defect, and because the inline
  `<c:url .../>` spelling never starts with `${` — three legitimate hrefs
  (UserEdit's Cancel, both tab layouts' menu links) are invisible to that
  grep entirely.
- A **message-argument escaping sweep**: `tiles/messages.jsp` renders
  errors and messages unescaped, deliberately, so the escaping boundary is
  the controller — and thirteen call sites had not noticed. All escaped,
  each with a failing-first unit test, and `MessageArgumentEscapingTest`
  is the ratchet.
- `AdminJspBugSweepTest` folded into `JspConsistencyTest` and deleted;
  `AdminJspHygieneTest#mainMenuSidebarDoesNotSkipHeadingLevels` deleted as
  subsumed by the tree-wide h4/h5 scan.

## 5. One thing the gates found that neither package introduced

The `/roller`-prefix pass failed `RouteSweepIT` on
`/roller-ui/createWeblog.rol` — a healthy 200 with site chrome and no form,
the `categoryEdit.rol` failure mode the sweep exists to catch. Traced, not
rerun: `GlobalConfigMatrixIT` turns `groupblogging.enabled` off (holding
`GLOBAL_CONFIG` in WRITE mode) to prove a second weblog is refused, and
while it is off `CreateWeblogController` answers `.GenericError` to an
admin who already owns a weblog. `RouteSweepIT` held no lock and the two
classes overlapped in that run.

A sweep over *every* admin route is sensitive to *every* site-wide flag any
other class permutes, so it now holds `GLOBAL_CONFIG` in READ mode — which
excludes the five writers without serialising it against the other readers.
Pre-existing, and invisible at the root context: the same tree ran 137/0/1
green there. This is the same shape as the `uploads.enabled` collision
CLAUDE.md already records for the media classes, and it is the second
reason in this task to distrust a green run at one context path.
