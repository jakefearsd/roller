# Stage 2 Wave 2 — Photography Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The spec's Wave 2: `[gallery]` shortcode with justified grid + self-hosted lightbox (captions, keyboard nav, EXIF overlay, blurhash placeholders, lazy load), password-protected share links for entries and galleries (Pixieset model), crop + focal point in admin with server-side re-encode, and a purpose-built portfolio theme.

**Architecture:** Executed from the fact base at `.superpowers/sdd/2026-08-02-stage2-wave2-photography/wave2-facts.md` (§-cites below; its "Top risks" are required reading for every task). Galleries are a convention on `MediaFileDirectory` (§4.2 — no new Gallery entity); the `[gallery]` handler registers in `ShortcodeExpander.DEFAULT` (§1.4) and emits sanitizer-surviving markup (§1.7) laid out by ~15 lines of flex-grow justified-grid CSS (§7.4). Lightbox = PhotoSwipe 5 webjar, self-hosted, loaded via a `#showGalleryAssets()` macro in the six theme heads (§2.2, §7.2-7.3). Share links = new `roller_share_link` table + `ShareController` on a `/share/*` prefix mapping following the Wave-1 `configure()` precedent (§3.4), rendered OUTSIDE the page cache (§3.6). Crop/focal = Cropper.js v2 webjar in admin (§7.5), server-side re-encode through `RenditionSupport.generate` regenerating ladder+thumb+blurhash+dims (Top risk 6).

**Locked decisions:** media-visibility gap closes FIRST (T1 — Top risk 1: without it shares are security theatre); InitFilter X-Forwarded-Proto fix rides in T1 (share URLs must be https-correct in prod); PhotoSwipe `org.webjars.npm:photoswipe:5.4.3` + `webjars` added to rollerProtectedUrls in the same commit (§7.3 caveat 2); grid CSS hand-rolled flex-grow (no dependency), `--ar` inline-style survival test written FIRST with bucketed-class fallback (§7.4); share token = new `util` TokenGenerator (SecureRandom→32B→URL-safe Base64, PIT-covered §7.6), password via `RollerContext.getPasswordEncoder()`; share unlock = session attribute, form carries `<sec:csrfInput/>` (§3.2-3.3, no ignoringRequestMatchers); gated media = share-scoped path `/share/<token>/media/<id>` + base path 404 for files in private directories + `Cache-Control: private, no-store` + sitemap exclusion (§8.3 option a); V007 is the migration; cropperjs 2.1.0 webjar (admin-only, no CSP constraint); crop is destructive (confirm dialog) and regenerates everything.

## Tasks

### T1: Close the platform gaps (prerequisite)
Two small, orthogonal, load-bearing fixes. (a) Media isolation: in `MediaResourceServlet` after the lookup (§8.1 `:101-102`), 404 when the URL's weblog != `mediaFile.getDirectory().getWeblog()`; regression test proving cross-weblog fetch fails (must fail against current code first); check the `?t=true` and `?w=` paths all sit behind the check. (b) Proto correctness: `InitFilter.java:108` hardcodes `http://` and nothing reads `X-Forwarded-Proto` — honor the header (Caddy sets it; also honor `request.isSecure()`), so absolute URLs (canonicals, og:url, sitemap locs, upcoming share URLs) are https under TLS termination. Add `server.forward-headers-strategy=framework` if appropriate for the servlet side — investigate which layer builds absolute URLs (InitFilter's absoluteUrl vs WebloggerRuntimeConfig) and fix at the root with tests for both proto cases. Full IT suite green. Commit: "Close the media-isolation and forwarded-proto gaps".

### T5: Password-protected share links
`ShareController` (template: SeoController §3.4.3 — isUserRequired/isWeblogRequired false, empty global perms, + override requiredWeblogPermissionActions): GET `/share/{token}` → resolves ShareLink (404 unknown/expired), no password → render; password + locked session → password form JSP (`<sec:csrfInput/>` §3.2); POST `/share/{token}` verifies via PasswordEncoder, stores session attribute, redirects. Share page renders the target (entry via its wrapper/transformed content, or directory as a gallery grid reusing T3's emission path) through a dedicated view OUTSIDE WeblogPageCache (§3.6 — dedicated controller render, no cache touch). Routing: `SHARE_URL_PATTERNS = {"/share/*"}` added in the existing `configure()` override (§3.4.2, keep bean name); `share` added to rollerProtectedUrls (§3.4.1). Gated media (locked decision, §8.3a): `/share/{token}/media/{fileId}?w=` serves files whose directory is share-covered (session-unlocked when password-protected), with `Cache-Control: private, no-store`; base media path 404s files in `is_private` directories (extend T1's check); T3's gallery emission uses share-scoped URLs when rendering inside a share page. Sitemap exclusion: SeoController skips noindex-style share-only content — entries stay (they're public), private directories' files never appear as image entries. Editor UI: share-link management card on MediaFileView (directory: create/copy-URL/set-password/revoke, is_private toggle) and EntryEdit sidebar (per-entry share) — reuse the existing bulk/CSRF patterns §5.2; message keys (MessageKeyTest ratchet note). Tests: controller unit+rendering tests (unknown/expired/wrong-password/unlock flow/cache-bypass proof: render, change content, re-render shows change), cross-weblog + locked-media tests, `RollerIT.getAnonymously` IT proving the gate (§6.4: anonymous fetch of gated page → password form; unlocked media 200; base path 404 for private dir) + Routes entries. Commit: "Add password-protected share links".
