# Stage 2 Wave 4 — Editor & Authoring QoL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The spec's Wave 4, as reshaped by the owner on 2026-08-03: Markdown is **mandated** as the storage format for all blog content rather than offered per entry, the editor becomes Markdown + a server-rendered preview, and the authoring quality-of-life set follows — post duplication, bulk publish/tag/delete on the entries list, and entry revisions with diff and restore.

**T1 and T2 are DONE and pushed** (`5b29b1c0d`, `900fd11be`, `31cf5c550`). What remains is T3–T7.

**Architecture (as built for T1/T2):** the mandate is structural — `content_type` and `content_src` are dropped in V009 and removed from pojo/ORM/bean/wrapper, so no second format can be expressed; `render()` converts unconditionally at both seams; the sanitizer is OWASP-based (it replaced 536 lines of regex) and is the security boundary, with raw HTML passing through Markdown by design; Summernote is deleted and EasyMDE is the editor, with the page owning one seam (`rollerSetEntryText`/`insertMediaFile`) that the browser tests drive.

**Original architecture note (superseded where it conflicts):** Executed from the fact base at `.superpowers/sdd/2026-08-02-stage2-wave4-editor/wave4-facts.md` (§-cites below; its "Top risks" are required reading per task). The format flag reuses the existing, verified-unused `weblogentry.content_type` column (§1) — **no migration for markdown**. Markdown conversion becomes one gated step in `WeblogEntry.render()`, **after** shortcode expansion and before the sanitizer (§2 — see the locked decision below; the intuitive order breaks every quoted shortcode attribute). Duplication uses the existing `WeblogEntry.setData()` primitive (§5). Revisions are full-text snapshots taken inside `saveWeblogEntry`, the single save funnel (§6), in **V009**.

**Locked decisions (revised 2026-08-03 — the opt-in model is REPLACED by a mandate):** every entry is Markdown, with no flag and no alternative format; conversion order is **shortcode expansion → markdown → sanitize** — the reverse of what it looks like it should be, and corrected during T1 against evidence: markdown-first escapes the quotes in `[gallery dir="X"]` to `&quot;`, which the expander's attribute grammar does not match, so every attribute-carrying shortcode would silently stop working in markdown entries. Expanding first is safe because commonmark passes raw HTML through verbatim in block and inline positions alike (verified against commonmark 0.24.0 for figure/picture/srcset/data-* and the `--ar` custom property). Cost: markdown syntax inside a shortcode's own emitted text is interpreted — cosmetic (§2, Top risk 1); commonmark-java pinned explicitly in `app/pom.xml` (not BOM-managed, §3) with the tables + autolink + strikethrough extensions; Summernote is REMOVED and EasyMDE is the only editor (§4); shortcode cards insert through the page's `insertMediaFile` seam, so the five shortcodes are declared once and the eventual WYSIWYG-for-Markdown changes one file; bulk actions copy `MediaFileView.jsp`'s proven checkbox + toggle-all + POST pattern and **must** go through `lookupEntry`'s ownership check and `removeEntryIndexOperation` per entry (§5 — Wave 2's fix-wave lesson); revisions store full text, not diffs, with diffs computed at view time (§6); retention keeps the newest 20 per entry, pruned in the same transaction; restore goes through the normal save funnel so it creates a revision of the pre-restore state (§6); `weblogentry_revision` gets `removeByEntry`/`removeByWeblog` named queries wired into weblog deletion (§6 — the FK-cascade trap Wave 2 hit).

## Tasks

### T1: The markdown render path — DONE (`900fd11be`)
No migration. `WeblogEntry`: treat `contentType` as the format flag with a small helper (`isMarkdown()`), documented as "any value other than `text/markdown` means HTML, as before". Add commonmark-java + extensions to `app/pom.xml` (§3). New `MarkdownRenderer` in `business/` (or alongside the shortcode package — pick and document): converts markdown → HTML with raw-HTML passthrough enabled. Wire ONE gated step into `WeblogEntry.render()` (§2), AFTER shortcode expansion and before the sanitizer: plugins → expand shortcodes → markdown → sanitize. `EntryBean` gains the field with copyTo/copyFrom (the five-edit pattern). Tests: the ordering fixture from Top risk 1 (a `[gallery]` inside a markdown list inside a blockquote — assert the gallery HTML survives and the markdown structure is right); an HTML entry renders byte-identically to master's output (the opt-in guard); a markdown entry emitting `<script>` is still stripped by the sanitizer (commonmark is not the security boundary); legacy junk in `content_type` takes the HTML path. Commit: "Render markdown entries".

### T2: The markdown editor — DONE (`31cf5c550`)
Choose the component (§4 lists the constraint: it must offer an insert-at-cursor API for T3, and ship as a webjar — verify the coordinates resolve before committing to it; Toast UI and Milkdown are the spec's candidates). Add the webjar; render it in `EntryEditor.jsp` **only when the entry is markdown**, Summernote otherwise — the branch belongs in the JSP with the flag from T1, and the two editors must never both initialize. Live preview: POST the draft text to a preview endpoint that runs the SAME `render()` path from T1 (never a client-side markdown library — the page would lie about shortcodes), debounce it, and render into a preview pane. A format toggle in the editor switches an entry between HTML and markdown: **converting an existing HTML entry to markdown must not silently mangle it** — decide and document (recommended: the toggle only sets the flag for entries that are empty or already markdown; changing an established HTML entry warns and requires confirmation). Message keys are JSP-referenced (ratchet). Tests: controller test for the preview endpoint (markdown in → expanded, sanitized HTML out; an HTML entry's preview matches its rendered output); a browser IT that writes markdown, sees the preview update, publishes, and asserts the public page. Commit: "Add the markdown editor with live preview".

### T3: Shortcode cards
One declaration of the five shipped shortcodes (`[image]`, `[gallery]`, `[map]`, `[cta]`, `[faq]`) with their attributes and a snippet template — server-side, exposed to the editor JSP so a sixth shortcode never needs a second edit site. A toolbar (or slash-menu) inserts the snippet at the cursor through the per-editor insert abstraction (§4: Summernote `pasteHTML` at `EntryEditor.jsp:124` today; the markdown editor's own API from T2). The `[image]`/`[gallery]` cards reuse the existing media chooser (Wave 1's callback passes the media-file id as its 4th arg). Preview renders them through the same expander as the page (T2's endpoint already does). Tests: unit test that the declaration and the rendered toolbar stay in step (a shortcode added to the registry but missing from the toolbar should fail); browser IT inserting a `[gallery]` from the toolbar in both editors. Commit: "Add shortcode insertion cards".

### T4: Post duplication
A "Duplicate" action on the entries list and/or the editor: `WeblogEntry.setData()` (§5) copies everything including the Wave-1 SEO block, then override id, anchor (**must be unique** — derive and de-duplicate), status `DRAFT`, pubTime/updateTime, and mark the title as a copy. Ownership-checked through `lookupEntry` like every other entry action. Tests: duplicate carries the SEO fields and content; the anchor is unique even when duplicating twice; the copy is a draft; a foreign entry id is refused. Commit: "Duplicate an entry".

### T5: Bulk actions on the entries list
`Entries.jsp` gains per-row checkboxes + toggle-all + a bulk action bar, copying `MediaFileView.jsp`'s pattern (§5) with `<sec:csrfInput/>`. `EntriesController` (read-only today) gains `@PostMapping`s for bulk publish, bulk tag-add, and bulk delete. **Every** bulk operation loops per entry through the ownership check AND, for delete, `removeEntryIndexOperation` (§5 — a bare bulk JPQL delete would orphan Lucene documents and reopen the cross-weblog hole Wave 2 closed). Partial failure must report which entries failed rather than rolling back silently. Tests: bulk publish flips only the selected entries; bulk delete removes index entries (assert via the search path); a foreign entry id in the selection is refused without affecting the others; CSRF absent → 403. Commit: "Add bulk actions to the entries list".

### T6: Revisions
V009: `weblogentry_revision` per §6's shape (id, entry FK, created, creator, title/text/summary), idempotent, `:app_user` grants, `SchemaMigrationTest.EXPECTED_TABLES` updated. `WeblogEntryRevision` pojo + orm + `persistence.xml` mapping-file + named queries `byEntry` (created DESC), `removeByEntry`, `removeByWeblog` — and wire `removeByWeblog` into `JPAWeblogManagerImpl.removeWeblogContents` (§6: the FK-cascade trap; regression-test weblog deletion with revisions present). Snapshot the PRE-save state inside `saveWeblogEntry`, prune to the newest 20 in the same transaction. UI: a revisions list on the entry editor, a diff view (compute at view time — pick a diff library or hand-roll a line diff; a webjar-free Java diff is fine), and Restore. Restore goes through the normal save funnel so the pre-restore state becomes a revision. Tests: N saves produce N-1 revisions with the right pre-save content; pruning keeps exactly 20 and drops the oldest; restore creates a revision and the entry matches the restored version; deleting a weblog with revisions succeeds; diff output is asserted on a known before/after. Commit: "Keep entry revisions with diff and restore".
