# W4 — Media: bulk upload and alt text Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An author can upload a folder of photographs in one go, and give each
one alt text that reaches every place the image is rendered.

**Architecture:** A new `mediafile.alt_text` column read by the two Java
emission points (`ImageShortcode`, `GalleryMarkup`) through
`MediaFileWrapper`, edited on `MediaFileEdit.jsp`, and surfaced-when-missing on
`MediaFileView.jsp`'s grid. Bulk upload is a form change only — the controller
already accepts `MultipartFile[]` and loops.

**Tech Stack:** PostgreSQL 16 + JPA/EclipseLink, Spring MVC, JSP/JSTL,
Bootstrap 5 + the Quiet Instrument tokens, JUnit 5, Selenide/Selenium.

**Spec:** `docs/superpowers/specs/2026-08-13-w4-media-design.md`.

## Global Constraints

- **Never push.** Commit per task as each task's final step says.
- Work directly on `master`. No feature branch.
- **Schema changes need a numbered migration** under `bin/db/migrations/`,
  idempotent, never editing one already applied. This wave owns **`V024`** and
  no other number.
- **`it-selenium/src/test/resources/seed-it-data.sql` is raw SQL with no
  compile-time or JPA check.** A migration dropping a column it writes fails the
  entire browser suite at fixture load, not at any test. Three waves have hit
  this. Check it in the migration task.
- **No hex colour literals in CSS.** `DesignTokenTest` fails on any hex that
  does not trace to `app/src/main/webapp/roller-ui/styles/roller-tokens.css`.
- **New message keys go in the base bundle only**
  (`app/src/main/resources/ApplicationResources.properties`), and must be
  referenced by a JSP or controller **in the same commit** — `MessageKeyTest`'s
  orphan ratchet refuses keys nothing references, and this is exactly what
  blocked W3's Task 1.
- **Never restyle by renaming a selector** — a content-tile marker change and
  its `it-selenium/.../support/Routes.java` update land in the same commit.
- **Velocity is lenient here**: a reference to a deleted Java member prints as
  literal text with no error and no failing test. Any task deleting a member
  reachable from a template must grep `app/src/main/webapp/themes` and
  `app/src/main/webapp/WEB-INF/velocity` before calling itself done.
- **Controllers must name `@RequestParam`/`@PathVariable` explicitly** — the
  build does not pass `-parameters`; `ControllerMetadataTest` enforces it.
- Run the **full** unit suite each task: `mvn -q -pl app test`. Baseline
  entering this wave: 3012 tests, 0 failures, 3 pre-existing skips.
- Read test counts from the surefire/failsafe **XML reports**, not Maven's
  console text.

### Task 2: The alt chain, at both places that emit one

**Files:**
- Modify: `app/src/main/java/org/apache/roller/weblogger/business/shortcodes/ImageShortcode.java`
- Modify: `app/src/main/java/org/apache/roller/weblogger/business/shortcodes/GalleryMarkup.java`
- Modify/Create: the matching `*Test` classes (find them; both have existing
  tests — follow their style rather than inventing a new one)

**Interfaces:**
- Consumes `MediaFileWrapper.getAltText()` from Task 1. Both call sites already
  hold a `MediaFileWrapper`, not a pojo — confirmed; no signature changes.
- Produces no new API.

The chain, identical at both sites:

```
explicit shortcode alt=  →  wrapper.getAltText()  →  wrapper.getName()
```

Blank counts as absent at every link (`StringUtils.isNotBlank`), not just null:
an author who clears the field leaves `""` behind, and `""` must fall through to
the next link rather than emitting `alt=""`, which claims the image is
decorative.

- [ ] **Step 1: `ImageShortcode`**

Replace line 114's

```java
        String alt = attributes.containsKey("alt") ? attributes.get("alt") : media.getName();
```

with a call to a small shared helper (see Step 2 for where it lives):

```java
        String alt = firstNonBlank(attributes.get("alt"), media.getAltText(), media.getName());
```

- [ ] **Step 2: `GalleryMarkup`**

Replace line 174's `escape(StringUtils.defaultString(image.getName()))` with the
same chain, minus the shortcode-attribute link (a gallery has no per-image
attribute to carry one):

```java
        html.append(" alt=\"")
                .append(escape(firstNonBlank(image.getAltText(), image.getName())))
                .append('"');
```

Put `firstNonBlank(String...)` wherever the two classes can share it without a
new class if one already exists in this package; otherwise duplicate the
three-line helper rather than introducing a utility class for it, and say in
your report which you did and why.

- [ ] **Step 3: Write the tests**

Both classes have existing test coverage. Add, for each:

- an image with alt text set → the alt attribute carries it, not the filename
- an image with alt text set to `"   "` → falls through to the filename
- an image with no alt text → the filename, unchanged from today
- (`ImageShortcode` only) an explicit `alt="..."` attribute → wins over the
  stored alt text

Assert on the emitted HTML, and assert the *absence* of the filename in the
first case — a test that only checks the alt text is present would pass if both
strings ended up in the attribute.

Run the two test classes, then `mvn -q -pl app test`.
Expected: PASS. Note that changing the default alt may break existing

Cover, in the voice of its neighbours:

- **The alt chain**, at both emission points: explicit shortcode `alt=` →

  and only one of them is the paged view an author with many photographs sees.
- **Alt text is deliberately absent from the upload form** — it is per-image,

  that the marker would then report as done.
- **Bulk upload is a form change only.** The controller always accepted
  `MultipartFile[]`; the ceiling was five fixed inputs in the JSP.
  `spring.servlet.multipart.max-request-size` is 1GB. A batch is not a
  transaction: quota is enforced per file inside `createMediaFile`, so a batch
  crossing `uploads.dir.maxsize` partway uploads the files before the crossing
  and refuses the rest — say what the page now reports in that case.
- **`MediaFile.sharedForGallery` and `mediafile.is_public` are gone** (V024),
