# Stage 2 Wave 1 — Media & SEO Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The spec's Wave 1: responsive image pipeline (width ladder + WebP + blurhash), EXIF extraction with GPS privacy, featured image per entry, automatic SEO baseline (canonical/OG/Twitter/JSON-LD) across all themes, XML + image sitemaps + generated robots.txt, per-entry SEO panel, and the generic shortcode expander that keeps Waves 2–5 order-independent.

**Architecture:** Executed from the fact base at `.superpowers/sdd/2026-08-01-stage2-wave1-media-seo/wave1-facts.md` (§-cites below; its "Top risks" list is required reading for every task). Renditions use the existing `_sm` sibling-suffix convention (`<id>_480|_960|_1600|_2400`, `+ .webp` when `cwebp` is present — feature-detected, never required); serving extends `MediaResourceServlet` with `?w=` + Accept-negotiation. The shortcode expander is a NEW unconditional step in both render call-sites (a deliberate, documented contract change). SEO emission is one global `#showSeoHead` macro inserted into all six theme heads. Sitemap/robots are Spring controllers reached by extending the DispatcherServlet's mappings. Editor gets an SEO accordion card + a featured-image picker reusing the media chooser (callback extended to pass the id).

**Locked decisions:** meta description REUSES `searchDescription` (no second column); renditions EXCLUDED from upload quota (skip `_`-suffixed files in `getDirSize`); GPS strip = global default ON (`uploads.exif.stripGps` in uploadSettings) applied to stored EXIF fields + renditions (original file kept intact); V006 is the migration; libraries per §8 (thumbnailator 0.4.21, metadata-extractor 2.21.0, hand-rolled blurhash + sitemap XML, cwebp CLI).
